Day-by-Day: What Each Day Actually Built

Day 1 Vectors & Matrices

Numbers-as-lists AND numbers-as-arrows are the same object, two lenses. array[i] drops a dimension, array[i:i+1] keeps it — the exact bug that breaks ML models expecting batch shape (1,n). Vectorization = push the loop into compiled C, 10–100x speedup, the pattern every training step reuses.

Day 2 Dot Product, Norm & Cosine Similarity

Dot product = raw agreement score, but confused by size (a "louder" vector fakes similarity). Cosine similarity fixes this by dividing out both norms — pure direction, -1 to +1. matrix @ matrix.T = everyone vs everyone in one shot — literally the core computation inside Transformer attention.

Day 3 Matrix Multiplication & NN Layers

Matmul = Day 2's dot product, repeated over a grid. Shape rule: cols_A == rows_B. output = ReLU((x @ W) + b) is the entire content of a neural network layer — stacked, that's a deep net. ReLU exists because stacked linear layers alone collapse into one linear layer — no curve-learning power without it.

Day 4 Transpose, Identity & Inverse

First day about undoing, not combining. A⁻¹ is defined purely by A @ A⁻¹ = I. det(A)=0 → no inverse exists (singular matrix — redundant info, unrecoverable). Matrices are NOT commutative — cancel from the same side only. This is the literal seed of how Linear Regression gets solved with zero training loop.

Day 5 Linear Regression — the Normal Equation

First real algorithm, closed-form: w = (XᵀX)⁻¹ Xᵀy. Bias trick (hstack a column of 1s). R² measures fraction of variance explained — but can be gamed by adding useless features (never lowers R²) or lie about future performance (memorization vs generalization). Multicollinearity → singular XᵀX → must test singularity on XᵀX (always square), never raw X.

Day 6 Gradient Descent

Why not always use (XᵀX)⁻¹: measured O(n³) cost yourself — 5000→10000 features was ~7x slower, not 2x. SSE is a U-shaped bowl (proven, not assumed — squared terms guarantee one minimum). Update rule: w_new = w − (lr × gradient) — always subtract. Feature scaling isn't optional here — unscaled data creates a "canyon" that blows up to NaN.

Day 7 Regularization — Ridge & Lasso

Fixes Day 5's open trap: tax large weights so noise stops looking useful. Ridge: w = (XᵀX + λI)⁻¹ Xᵀy — smooth circular boundary, shrinks but rarely zeroes. Lasso: diamond boundary with corners → soft-thresholding → can delete features outright, but has no closed form (needs coordinate descent) and is scale-sensitive in a different, sharper way than Gradient Descent. Elastic Net (both penalties) named as the fix for Lasso's "arbitrary winner" weakness — not built by hand yet.

Live Review Session — Corrections That Actually Mattered

Today's spot-check surfaced three precise misconceptions worth locking in permanently — these are exactly the kind of details interviewers probe for.
Correction 1 — What λI actually touches.
Said: "adds a small positive value to every entry."
Reality: λI only touches the diagonal — off-diagonal entries of XᵀX (the feature-to-feature covariance terms) stay completely untouched. This is exactly why I[0,0]=0 works so cleanly to exclude the bias — you're zeroing one specific diagonal cell, nothing else.
Locked-in version: λI inflates each feature's own "self-energy" (diagonal) just enough to break ties caused by near-duplicate columns, without distorting the real relationships between features.
Correction 2 — Why Gradient Descent breaks on unscaled data.
Said: "it takes large/small steps without thinking."
Reality: the real problem is a single learning rate has to serve every feature dimension at once. Unscaled features create a canyon — steep in one direction, flat in another. Safe-for-steep is too slow on flat; safe-for-flat overshoots and explodes on steep. There's no single lr that works for both — that's the actual mechanism, not just "big steps happen."
Locked-in version: scaling reshapes the canyon back into a round bowl so one learning rate is fair in every direction simultaneously.
Correction 3 — Why Lasso is scale-sensitive.
Said: "scaling gives Lasso more confidence to choose."
Reality: it's not about confidence — it's a fixed threshold compared against a per-feature rho_j that scales with the feature's own raw units. A 60x-bigger-scale feature produces a proportionally bigger rho_j purely from unit size, so it clears the same fixed threshold more easily — nothing to do with real importance.
Locked-in version: unscaled, Lasso is unfair, not cautious — it rewards big raw numbers. Scaling makes the competition fair, though the final winner among true duplicates is still close to arbitrary (loop-order dependent).
Correction 4 — Normal Equation vs Gradient Descent trigger.
Said: "large dataset → use Gradient Descent."
Reality: the deciding factor is feature count, not row count. XᵀX is a (features × features) matrix — that's what gets inverted, and that's what's O(n³). Row count is cheap for both methods.
Locked-in version, with your own measured numbers: "5,000→10,000 features took inversion from 3.2s to 23.8s — a 7x slowdown from a 2x size increase. At millions of features, that's not just slow, it's impossible."
