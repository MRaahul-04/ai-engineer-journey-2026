Day 15 — Decision Trees

Week 3 · Day 15 of 84 · AI Engineer Journey 2026

The one-line idea

Weeks 1–2 lived entirely in the regression family: weights, gradients, probability curves. Today is a completely different paradigm — a tree that learns by asking a sequence of yes/no questions on the raw feature values. No distance, no gradient descent, no probability distribution. Just: split the data, again and again, wherever it separates the classes best.

Gini Impurity — derived, not memorized

The real question: if you reach into a group and pull out 2 random members (with replacement), what's the probability their labels don't match? 
Group: 2 Pass, 1 Fail (out of 3)  ->  p_pass=2/3, p_fail=1/3

P(mismatch) = P(pass then fail) + P(fail then pass)
            = (2/3 × 1/3) + (1/3 × 2/3) = 2/9 + 2/9 = 4/9 ≈ 0.4444
That IS Gini Impurity: 
Gini = 1 - Σ p_i²
     = 1 - ((2/3)² + (1/3)²) = 1 - (4/9 + 1/9) = 1 - 5/9 = 4/9 ✓
Two derivations, same number — pairwise-mismatch probability and "1 minus sum of squared proportions" are algebraically identical.

Range: Gini=0 → perfectly pure (all one label). Gini=0.5 → worst possible mixing for 2 classes (50/50).

Weighted Gini — combining two child groups fairly

A split always makes TWO groups. Plain averaging their Gini scores would let a tiny, noisy group count just as much as a huge, clean group — wrong. Weight each side by its share of the total data: 
Gini_split = (n_left/n_total)×Gini_left + (n_right/n_total)×Gini_right

Example: left(n=3, gini=0.4444), right(n=9, gini=0.1), total=12
= (3/12)(0.4444) + (9/12)(0.1) = 0.1111 + 0.075 = 0.1861
The algorithm's entire job: compute this number for every candidate split, pick the smallest (purest) one.

Worked example — Hours vs Attended

6 students, Hours Studied + Attended(Y/N) → Pass/Fail. 
Split "Hours > 5":     {A,C,E} all Pass | {B,D,F} all Fail
                        Gini=0 + Gini=0 -> weighted Gini = 0.0  ← WINNER

Split "Attended?":     {A,B,E}=2Pass/1Fail | {C,D,F}=1Pass/2Fail
                        Gini=0.4444 + Gini=0.4444 -> weighted Gini = 0.4444
The tree doesn't "see" or "reason" — it just computes both numbers and keeps the smaller one. 0.0 beats 0.4444, so "Hours > 5" wins, exactly matching human intuition — but now provably, not just visually.

Entropy — the information-theory alternative

Entropy = -Σ p_i log₂(p_i)
Built from "bits": a fair coin (2 equally likely outcomes) takes exactly 1 yes/no question to resolve → log₂(2) = 1 bit. A rigged 99%-Heads coin needs far fewer questions on average — rare events carry more "surprise" (more bits), common events carry less. Entropy = average surprise across all outcomes, weighted by their own probability. 
Group: 2 Pass, 1 Fail   log₂(2/3)≈-0.585   log₂(1/3)≈-1.585

Entropy = -[(2/3)(-0.585) + (1/3)(-1.585)] = -(-0.390-0.528) = 0.9183
Same shape as Gini: 0 at perfect purity, max at 50/50 (Entropy maxes at 1.0, Gini maxes at 0.5 — different scales, same behavior).

Gini vs Entropy — why Gini is sklearn's default

Not about accuracy — almost always pick the same splits. It's about computational cost: Gini needs only p² (cheap multiply); Entropy needs p·log₂(p) (expensive logarithm). A tree recomputes this at every candidate threshold, every feature, every node — potentially millions of times on real data. sklearn defaults to Gini purely for speed.

Choosing candidate thresholds — midpoints, not raw values

Testing every integer wastes work. Only points where the split's outcome can actually change matter — and that's the midpoint between each pair of consecutive sorted unique values, not the values themselves. 
sorted unique hours: [1, 2, 3, 7, 8, 9]
midpoints (n-1 of them): [1.5, 2.5, 5.0, 7.5, 8.5]
Threshold below the min or above the max always dumps EVERYONE into one side, leaving the other side empty — gini([]) trivially returns 0 but tells the algorithm nothing real. That's why the guard if len(labels)==0: return 0 exists — to survive that edge case cleanly, not to reward it.

From-scratch build — the 4 core functions

def gini(labels):
    if len(labels) == 0:
        return 0
    _, counts = np.unique(labels, return_counts=True)
    proportions = counts / len(labels)
    return 1 - np.sum(proportions ** 2)

def weighted_gini(left_labels, right_labels):
    n_left, n_right = len(left_labels), len(right_labels)
    n_total = n_left + n_right
    return (n_left/n_total)*gini(left_labels) + (n_right/n_total)*gini(right_labels)

def best_split_for_feature(feature_values, labels):
    sorted_unique = np.sort(np.unique(feature_values))
    best_gini, best_threshold = float('inf'), None
    for i in range(len(sorted_unique) - 1):
        threshold = (sorted_unique[i] + sorted_unique[i+1]) / 2
        mask = feature_values > threshold
        current_gini = weighted_gini(labels[mask], labels[~mask])
        if current_gini < best_gini:
            best_gini, best_threshold = current_gini, threshold
    return best_threshold, best_gini

def best_split_overall(X, y, feature_names):
    best_feature, best_threshold, best_gini = None, None, float('inf')
    for i in range(X.shape[1]):
        threshold, gini_score = best_split_for_feature(X[:, i], y)
        if gini_score < best_gini:
            best_feature, best_threshold, best_gini = feature_names[i], threshold, gini_score
    return best_feature, best_threshold, best_gini
Verified on our data: WINNER → feature='hours', threshold=5.0, gini=0.0000

Stopping conditions — trees overfit too, same lesson as Day 5/7

1. Pure group (Gini≈0): every threshold gives weighted_gini=0 — no mixing left to reduce, so splitting further is wasted work that accomplishes nothing.

2. Too few samples: 1 unique value in a feature → the threshold loop runs ZERO times (range(0)) → silently returns threshold=None instead of crashing. Must be explicitly guarded, or downstream code breaks on None.

3. max_depth: a global, structural cap on how many levels deep the tree can grow — independent of how much data is in any node.
The overfitting connection (Day 5 callback): a tree split all the way to single-student leaves is just a giant memorized lookup table — same disease as Linear Regression's SSE=0 trap (#rows=#unknowns → perfect but meaningless fit). A brand-new student matching no exact leaf gets no generalized rule. min_samples_split/max_depth are trees' version of Ridge/Lasso's λ.

Recursive tree builder

def build_tree(X, y, feature_names, depth=0, max_depth=5, min_samples_split=2):
    if gini(y) == 0:
        return {'leaf': True, 'prediction': y[0]}
    if len(y) < min_samples_split or depth >= max_depth:
        values, counts = np.unique(y, return_counts=True)
        return {'leaf': True, 'prediction': values[np.argmax(counts)]}

    best_feature, best_threshold, _ = best_split_overall(X, y, feature_names)
    if best_threshold is None:
        values, counts = np.unique(y, return_counts=True)
        return {'leaf': True, 'prediction': values[np.argmax(counts)]}

    feature_index = feature_names.index(best_feature)
    mask = X[:, feature_index] > best_threshold
    left  = build_tree(X[mask],  y[mask],  feature_names, depth+1, max_depth, min_samples_split)
    right = build_tree(X[~mask], y[~mask], feature_names, depth+1, max_depth, min_samples_split)
    return {'leaf': False, 'feature': best_feature, 'threshold': best_threshold,
            'left': left, 'right': right}
Base case first, recurse only if needed — the exact same shape as every recursive algorithm. Stopping conditions return immediately; otherwise the function does work and calls itself on smaller pieces.

Our tree, fully built

[hours > 5.0 ?] / \ YES NO | | leaf: PASS (1) leaf: FAIL (0) {A,C,E}: all Pass {B,D,F}: all Fail both groups pure -> recursion stops immediately

Prediction — walking the tree

def predict_one(tree, x, feature_names):
    if tree['leaf']:
        return tree['prediction']
    feature_index = feature_names.index(tree['feature'])
    if x[feature_index] > tree['threshold']:
        return predict_one(tree['left'], x, feature_names)
    else:
        return predict_one(tree['right'], x, feature_names)
Traced for a new student (hours=6, attended=1): 6 > 5.0 → True → go left → leaf → return 1 (Pass). Recursive walk down, mirroring the recursive build up.

Interview questions — plain-language answers

Q1. Why don't Decision Trees need feature scaling?
Trees split using simple greater-than/less-than rules on one feature at a time — rank-based, not distance- or gradient-based. Multiplying a feature by 1000 never changes which side of a threshold a point falls on, so the order (all a tree cares about) is preserved regardless of scale. This is unlike kNN (raw-scale distance dominance) or Gradient Descent-based models (canyon problem).
Q2. max_depth vs min_samples_split — same problem or different?
Different, complementary angles on overfitting. max_depth is a global structural cap — limits vertical size regardless of data volume in any node. min_samples_split is a local, data-driven cap — stops a specific node from splitting if it doesn't hold enough samples to split reliably, regardless of depth. Often tuned together.
Q3. What happens on an exact Gini tie between two features at the root?
Implementation detail, not a principled choice — sklearn picks by column/iteration order, first one checked wins ties. This matters because the root split cascades into completely different subtrees below it — a source of real model instability where small data changes (or even just column order) can produce a structurally different tree at the same accuracy. Motivates Random Forests (averaging many trees smooths this out).
