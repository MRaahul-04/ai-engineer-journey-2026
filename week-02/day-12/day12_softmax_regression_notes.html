Day 12 — Softmax Regression

Week 2 · Day 12 of 84 · AI Engineer Journey 2026

The one-line idea

Day 9's sigmoid answers exactly one yes/no question. Today: what happens with 3+ classes (Fail / Pass / Distinction)? Sigmoid doesn't generalize on its own — softmax is the fix, and it turns out sigmoid was always just softmax's 2-class special case all along.

Why one-vs-rest sigmoids break

Train 3 independent sigmoids, one per class. For a student with hours=7: 
Sigmoid A (Fail?):        0.05
Sigmoid B (Pass?):        0.62
Sigmoid C (Distinction?): 0.51

Sum = 0.05 + 0.62 + 0.51 = 1.18   <- should be exactly 1.00
Root cause: each sigmoid is trained independently, with zero awareness the other classes even exist. No shared constraint forces them onto one 100% pie. Also causes ambiguous overlaps (Pass 0.62 and Distinction 0.51 both say "probably me").

Building Softmax from first principles

Need: turn raw scores into numbers that (1) are always positive, (2) sum to exactly 1. Naive division on raw z breaks (negatives explode). Steal Day 9's trick — exponentiate first (e^z is always positive), then normalize: 
softmax(z_i) = e^(z_i) / Σ e^(z_j)     (sum over all classes j)

z = [-2.0, 1.5, 1.2]
e^z = [0.135, 4.482, 3.320]
sum = 7.937
p = [0.017, 0.565, 0.418]     <- sums to exactly 1.000 ✓
Dividing by the shared sum forces every class to compete for the same fixed pie — a bigger score for one class steals share from the others, automatically.

Softmax IS sigmoid — proven, not assumed

Shrink to 2 classes and simplify algebraically: 
p_Pass = e^(z_Pass) / (e^(z_Fail) + e^(z_Pass))
       = 1 / (1 + e^(-(z_Pass - z_Fail)))    <- exactly sigmoid!
Sigmoid was never a separate algorithm — it's softmax's exact 2-class case, using the difference between two classes' raw scores as its single z.

Numerical stability — the overflow bug, live

z_big = np.array([1000, 1, 1])
np.exp(z_big)   -> RuntimeWarning: overflow encountered in exp -> inf
inf / inf → nan. Real trap with real neural network logits, not hypothetical.
Fix — subtract the max first. Proven algebraically that this never changes the output (the constant cancels top and bottom): 
def softmax(z):
    z_shifted = z - np.max(z)
    exp_z = np.exp(z_shifted)
    return exp_z / np.sum(exp_z)

softmax([1000, 1, 1]) -> [1., 0., 0.]   <- no overflow, no nan

Batch version — the broadcasting bug, live

Z = np.array([[-2.0, 1.5, 1.2], [3.0, 0.5, -1.0]])   # shape (2,3)
maxes = np.max(Z, axis=1)                             # shape (2,)
Z - maxes
-> ValueError: operands could not be broadcast together with shapes (2,3) (2,)
Day 1's exact lesson again: maxes lost its dimension when reduced. NumPy can't tell if that 2 means rows or columns.
Fix — keepdims=True. Keeps the reduced axis as size 1 instead of dropping it, so shapes line up (3 vs 1 broadcasts, 2 vs 2 matches): 
def softmax_batch(Z):
    Z_shifted = Z - np.max(Z, axis=1, keepdims=True)
    exp_Z = np.exp(Z_shifted)
    return exp_Z / np.sum(exp_Z, axis=1, keepdims=True)
Same keepdims=True needed for the denominator sum too — each student's row must divide by that row's own sum, not a global one.

One-hot encoding — a one-line trick

np.eye(n_classes)'s row k IS already the one-hot vector for class k (1 at its own position, 0 elsewhere — literally the identity matrix's definition). So indexing the identity matrix with the whole label array one-hot-encodes everything at once: 
def one_hot(y, n_classes):
    return np.eye(n_classes)[y]

one_hot([0,1,2,1,0], 3)
-> [[1,0,0], [0,1,0], [0,0,1], [0,1,0], [1,0,0]]

Categorical Cross-Entropy — same self-selecting trick as Day 9

y_onehot * log(p):
[0,1,0]·log([0.017,0.565,0.418]) -> [0, -0.571, 0]   <- zeros kill wrong terms
sum -> -0.571, negate -> 0.571                       <- matches Day 9's pattern exactly

CCE = -(1/n) · Σ_samples Σ_classes  y_i · log(p_i)
Collapses exactly to Day 9's Binary Cross-Entropy when there are only 2 classes — same mechanism, just N slots instead of 2.

The log(0) landmine

np.log(p) runs on the WHOLE matrix before multiplying by y_onehot. If any p entry is exactly 0 (possible after stable softmax), log(0) = -inf, and 0 * (-inf) = nan — NOT the 0 you'd expect. One nan poisons the entire sum.
Fix — clip probabilities away from the exact edges: 
def categorical_cross_entropy(y_onehot, p, epsilon=1e-15):
    p_clipped = np.clip(p, epsilon, 1 - epsilon)
    n_samples = y_onehot.shape[0]
    return -np.sum(y_onehot * np.log(p_clipped)) / n_samples
Same category of fix as Day 9's asymptotic sigmoid (never touches exactly 0 or 1) — applied defensively here for floating-point edge cases.

The gradient — Day 9's cancellation strikes again

Because softmax IS sigmoid generalized, the same chain-rule cancellation happens: 
Day 9  (Logistic Reg): gradient = Xᵀ(predictions - y)
Day 12 (Softmax Reg):  gradient = Xᵀ(predictions - y_onehot)
Shape traced by hand: X_b.T is (3,5), (predictions - y_onehot) is (5,3) → matmul gives (3,3) — matches W's own shape (n_features+1, n_classes) exactly, as it must (gradient updates W directly).

SoftmaxRegressionScratch — the full class

class SoftmaxRegressionScratch:
    def __init__(self, learning_rate=0.1, n_iterations=1000):
        self.learning_rate = learning_rate
        self.n_iterations = n_iterations
        self.loss_history = []

    def fit(self, X, y, n_classes):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        y_onehot = np.eye(n_classes)[y]
        self.W = np.zeros((X_b.shape[1], n_classes))

        for i in range(self.n_iterations):
            Z = X_b @ self.W
            predictions = softmax_batch(Z)
            gradient = X_b.T @ (predictions - y_onehot) / X_b.shape[0]
            self.W = self.W - self.learning_rate * gradient
            loss = categorical_cross_entropy(y_onehot, predictions)
            self.loss_history.append(loss)
        return self

    def predict_proba(self, X):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        return softmax_batch(X_b @ self.W)

    def predict(self, X):
        return np.argmax(self.predict_proba(X), axis=1)
np.argmax(..., axis=1) — per student's row, returns the index of the largest probability (the winning class).

The "expected first loss" sanity check

At W = zeros, every z=0, so softmax([0,0,0]) = [1/3, 1/3, 1/3] for every student regardless of true label. First loss = -log(1/3) = 1.0986 — always, for zero-init softmax. General rule: -log(1/n_classes) is the expected starting loss — a reusable "is training even working" gut-check for any future multi-class problem.

Confirmed on 9-student clean dataset (hours only, gaps at 3→4, 6→8): first loss=1.0986, final loss=0.1822, predictions 9/9 correct.

Interview questions — plain-language answers

Q1. Why can't you just use sigmoid for 3+ classes?
One-vs-rest sigmoids are trained independently with no shared constraint — outputs don't sum to 1 and can produce ambiguous overlaps. A real probability distribution over mutually exclusive classes must sum to exactly 1.00; nothing about independent sigmoids guarantees that.
Q2. What does softmax do, mechanically?
Exponentiates every raw score (guaranteeing positivity), then divides each by the sum of all of them — forcing every class to compete for the same fixed 100% pie.
Q3. Is softmax related to sigmoid, or a different algorithm?
Sigmoid is softmax's exact 2-class special case — provable algebraically, reduces to 1/(1+e^-(z_Pass-z_Fail)).
Q4. Why the "subtract the max" trick?
Prevents float overflow on large raw scores (e^large → inf → nan). Provably doesn't change the output — the subtracted constant cancels top and bottom in the softmax formula.
Q5. Why does CCE use y·log(p) instead of squared error?
One-hot zeros self-select only the true class's term (no if/else needed), and -log(p) has no ceiling — punishes confident wrongness with unbounded loss, keeping the gradient strong exactly where correction matters most.
Q6. Why is the softmax gradient almost identical to logistic regression's?
Same chain-rule cancellation as Day 9, since softmax IS sigmoid generalized — simplifies to Xᵀ(predictions - y_onehot), only difference being softmax instead of sigmoid and a full weight matrix instead of a vector.
Q7. Does more training fix a wrong prediction from a 1-feature model?
Not if the true pattern genuinely can't be traced by one monotonic feature — proven directly in homework, where 2 points stayed wrong regardless of training until a 2nd feature was added.
Q8. Why do scratch and sklearn weights differ even with identical predictions?
sklearn's default L2 regularization shrinks weights toward zero (Day 7's Ridge idea, carried into classification) — same decision boundary, different confidence/aggressiveness getting there.
Q9. What does -log(1/n_classes) tell you?
The expected loss at zero-initialization, since uniform 1/n_classes probabilities come from all-zero raw scores — a reusable "is training working" sanity check for any multi-class problem.
