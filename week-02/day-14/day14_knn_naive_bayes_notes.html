The one-line idea

Days 9-13 all built ONE family: regression-based classifiers (sigmoid/softmax + gradient descent). Today we meet two genuinely different families — kNN (compare to nearby points, no training at all) and Naive Bayes (probability + Bayes' Theorem). Both get evaluated immediately using Day 13's fresh macro/micro/weighted F1 toolkit — B→A sequencing complete.
Part 1 — k-Nearest Neighbors

The core intuition — no formula first

New student's dot on a chart of (hours, attendance). Old students scattered around, each labeled Pass/Fail. The physically closest dots should count more than distant ones — don't average all 20 equally, just pick the k closest and let them vote by majority. That's the ENTIRE algorithm. No weights, no loss function, no gradient descent.

Euclidean distance — Day 1's Pythagoras, reused

"Closeness" between two vectors = subtract them first (Day 1's arrow-difference), THEN apply Day 1's length formula to that difference vector: 
diff = point1 - point2          # e.g. [6,55]-[4,58] = [2,-3]
squared = diff ** 2              # [4, 9]
total = sum(squared)             # 13
distance = sqrt(total)           # 3.6055
np.linalg.norm(point1 - point2) does this in one call — same Day 4 tool, applied to a difference instead of a raw vector.

The full recipe

  1. Choose k (decided beforehand, e.g. k=3)
  2. Compute distance from new point to EVERY training point
  3. Sort distances smallest→largest (np.argsort — returns indices, not values)
  4. Take the top k closest indices
  5. Majority vote among those k labels (np.bincount + np.argmax)

From scratch — full class (verified vs sklearn: [0 1 0] both)

class KNNClassifierScratch:
    def __init__(self, k=5):
        self.k = k

    def fit(self, X, y):
        self.X_train = X
        self.y_train = y
        return self

    def _euclidean_distance(self, point1, point2):
        diff = point1 - point2
        return np.sqrt(np.sum(diff ** 2))

    def _predict_one(self, new_point):
        distances = [self._euclidean_distance(new_point, x) for x in self.X_train]
        sorted_indices = np.argsort(distances)
        k_nearest_indices = sorted_indices[:self.k]
        k_nearest_labels = self.y_train[k_nearest_indices]
        counts = np.bincount(k_nearest_labels)
        return np.argmax(counts)

    def predict(self, X):
        return np.array([self._predict_one(x) for x in X])
fit() is genuinely just 2 lines — "lazy learner" made literal. All real work happens inside predict().

"Lazy learner" / non-parametric — why it matters

Parametric (Linear/Logistic/Softmax Reg): fixed-size weight vector w learned upfront in fit(); training data can be discarded afterward; predict() is cheap regardless of dataset size.

kNN (non-parametric): NO fixed parameters at all — the model IS the stored training data. fit() does almost nothing; predict() must scan ALL training points every single time. Prediction gets slower as the dataset grows — a real production bottleneck at scale (fixed by KD-trees/ball trees — name to remember, not built).

The scaling trap — same canyon, new mechanism

Euclidean distance sums raw feature values directly. hours ranges 1-9, attendance ranges 45-95 — attendance's bigger raw scale silently dominates every distance calculation, regardless of which feature is actually more predictive. Proven: 7-hour gap → distance=7; 40-point attendance gap → distance=40 — attendance wins purely on units, not on real signal.
Same fix as Day 6/Day 9: standardize before computing any distance. 
mean = X_train.mean(axis=0)
std  = X_train.std(axis=0)
X_train_scaled = (X_train - mean) / std
X_test_scaled  = (X_test - mean) / std     # REUSE training mean/std, never refit on test
Always fit scaling params on training data only — a test set standardized on its own mean loses all real comparability to training data.

Choosing k — the bias-variance tradeoff, proven with a real sweep

k=1,3    -> F1=0.8750   (noisy, overfits to individual outlier points)
k=5-11   -> F1=0.9091   (smoothing starts to help)
k=15-51  -> F1=0.9412   (best zone — tied across several k values)
k=84     -> F1=0.0000   (collapsed to "always predict majority class")
Small k = low bias, high variance (hugs data tightly, sensitive to noise). Large k = high bias, low variance (smooth but ignores local structure, degenerates toward majority-class-only at the extreme).

Tie-breaking rule: among tied-best k values, prefer the smallest — safer, less likely to be secretly relying on "just guess majority." Also prefer odd k in binary classification to avoid vote ties.
Part 2 — Gaussian Naive Bayes

Bayes' Theorem — built from a real medical example

Disease affects 1% of population. Test is 90% accurate on sick people, 5% false positive rate on healthy people. Out of 1,000 people: 
10 actually sick   -> 9 test positive (true positives)
990 actually healthy -> ~50 test positive anyway (false positives)

Total positive = 9 + 50 = 59
P(Disease | Positive) = 9/59 ≈ 15%     <- NOT 90%!
A "90% accurate" test only gives ~15% real confidence when the disease is rare — because the huge healthy population generates more false alarms than the tiny sick population generates true detections. 
P(Class | Features) = P(Features | Class) × P(Class) / P(Features)
Prior P(Class) = belief before evidence. Likelihood P(Features|Class) = chance of this evidence, given the class. Posterior P(Class|Features) = updated belief after evidence — what we actually want, to predict Pass/Fail from hours/attendance.

Why "naive" — the independence assumption

Computing the TRUE joint probability of multiple features together is hard (needs huge data to estimate reliably). Naive Bayes just assumes every feature is independent given the class — even if false in reality — so it can multiply individual feature probabilities instead: 
P(hours, attendance | Class) ≈ P(hours | Class) × P(attendance | Class)
Why it still works well: classification only needs the correct ranking between classes, not perfectly calibrated exact probabilities. The wrong assumption often distorts every class's score similarly, so the winner still comes out right even when the raw numbers are miscalibrated.

Gaussian PDF — probability for continuous features

Can't ask "P(hours = exactly 6.0)" for continuous data — always ≈0. Instead: how "typical" is 6.0 given this class's mean and spread? 
P(x | Class) = 1/√(2πσ²) · e^(-(x-μ)² / 2σ²)
Verified by hand: at x=mean, output peaks (0.332 for mean=7.14,std=1.2). Far from mean (x=20) → collapses to ≈3.8×10⁻²⁶ — essentially "impossible" for that class.

Log-probabilities — preventing underflow

Multiplying many small probabilities (e.g. 20 features, each ~10⁻²⁶) risks floating-point underflow — the product silently rounds to exactly 0.0, destroying all information.
Same log-space trick as Day 9/12: log(a×b) = log(a) + log(b). Add logs instead of multiplying raw values — log is monotonic, so the ranking between classes survives, but numbers stay numerically safe.

GaussianNaiveBayesScratch — full class (verified vs sklearn: [0 1 0] both)

def gaussian_pdf(x, mean, std):
    exponent = -((x - mean) ** 2) / (2 * std ** 2)
    coefficient = 1 / np.sqrt(2 * np.pi * std ** 2)
    return coefficient * np.exp(exponent)

class GaussianNaiveBayesScratch:
    def fit(self, X, y):
        self.classes = np.unique(y)      # generalizes to ANY number of classes
        self.means = {}
        self.stds = {}
        self.priors = {}
        for c in self.classes:
            X_c = X[y == c]
            self.means[c] = X_c.mean(axis=0)
            self.stds[c] = X_c.std(axis=0)
            self.priors[c] = len(X_c) / len(X)
        return self

    def _predict_one(self, x):
        scores = {}
        for c in self.classes:
            log_score = np.log(self.priors[c])
            for i in range(len(x)):
                log_score += np.log(gaussian_pdf(x[i], self.means[c][i], self.stds[c][i]))
            scores[c] = log_score
        return max(scores, key=scores.get)   # returns winning CLASS LABEL, not the score

    def predict(self, X):
        return np.array([self._predict_one(x) for x in X])
Real traced numbers for the tricky student [6,55]: 
log_score_fail ≈ -6.17    log_score_pass ≈ -53.77   -> predicts Fail (correct!)
np.unique(y) instead of hardcoded masks means this same code works for 2 classes or 20 classes, no rewrite needed (Day 12's softmax generality, reused).

Zero-frequency problem & Laplace smoothing

If a categorical feature value NEVER appeared in training for some class, its probability estimate is exactly 0. In log-space: log(0) = -inf — that class is permanently ruled out, regardless of how strongly every other feature pointed toward it.
Laplace smoothing: add a small constant (usually 1) to every count before computing probabilities — guarantees no estimate is ever exactly 0. Matters far more for categorical/discrete NB (text/spam) than Gaussian NB (continuous PDFs rarely hit a hard zero).

Why Gaussian NB doesn't need feature scaling (unlike kNN)

kNN combines ALL features into ONE shared distance number — a big-scale feature dominates that combination. Gaussian NB computes each feature's PDF completely separately, against its OWN mean/std — never combined until the final log-sum. Each feature is judged fairly on its own natural scale from the start, so scaling isn't required for correctness.
Head-to-Head: Day 13's Imbalanced Dataset (300/15/8)

Real comparison — Macro F1 exposes a genuine weakness

kNN (k=15):   Macro F1=0.5148   Micro F1=0.9485   Weighted F1=0.9322
GaussianNB:   Macro F1=0.8482   Micro F1=0.9794   Weighted F1=0.9772
Confusion matrices: kNN missed 3/5 of class 1 and ALL of class 2 (0/2 correct). GaussianNB missed only 1/5 of class 1 and caught 1/2 of class 2. Micro/Weighted F1 look "fine" for both (~0.93-0.98) — only Macro F1 exposes kNN's real minority-class failure — Day 13's lesson, now proven on a brand-new model family.

Why kNN struggles more on imbalance

With majority class hugely outnumbering rare classes, a rare point's k=15 nearest neighbors statistically tend to include majority-class points nearby — diluting the rare class's vote. Gaussian NB has no such vulnerability — it just asks "which class's mean/spread fits best," independent of how many training points that class has.

Rebalancing knobs — algorithm-level vs data-level

GaussianNB has a priors parameter — manually set custom class priors, similar spirit to class_weight='balanced'. kNN has NO class_weight equivalent — no loss function to reweight at all (closest lever: weights='distance', weights closer neighbors more heavily, doesn't fix imbalance directly). Algorithms WITH a loss function can rebalance via reweighting; algorithms WITHOUT one (kNN) need a DATA-level fix instead (resampling — oversampling/undersampling, named Day 13, still not built).

Interview Q&A — kNN

Q1. Why is kNN a "lazy learner"?
fit() only stores data — no real computation happens until predict(), unlike "eager learners" (Logistic Regression) that do all learning upfront.
Q2. Small k vs large k?
Small k (e.g. 1): high variance, overfits to noise/outliers. Large k (approaching full dataset size): high bias, underfits, degenerates toward always predicting the majority class.
Q3. Why must you scale features before kNN?
Euclidean distance sums raw feature values into one combined number — a bigger-scale feature silently dominates distance regardless of true importance.
Q4. Why "non-parametric"?
No fixed, compressed parameter set (like a weight vector) — the training data itself IS the model; complexity/size grows directly with data volume.
Q5. Major production weakness vs Logistic Regression?
Prediction cost grows with training set size (must scan all stored points every time) — Logistic Regression's prediction cost stays constant regardless of training set size.

Interview Q&A — Naive Bayes

Q1. What does "naive" mean here?
Assumes all features are conditionally independent given the class — often false, but makes the joint probability computable via simple multiplication.
Q2. Why does it work despite a false assumption?
Classification only needs correct ranking between classes, not calibrated exact probabilities — the assumption distorts all classes similarly, so the winner usually still comes out right.
Q3. Why log-probabilities instead of raw?
Multiplying many small probabilities risks underflow (product rounds to exactly 0.0). Logs turn multiplication into addition — ranking preserved, numerically safe.
Q4. What's the zero-frequency problem, and the fix?
An unseen feature value gives probability 0, forcing that entire class's score to -inf (log-space) regardless of other evidence. Fixed via Laplace smoothing — add a small constant to every count before computing probabilities.
Q5. How does Gaussian NB's training cost compare to kNN's?
Gaussian NB IS a real eager learner — fit() computes and stores compressed mean/std/prior statistics; predict() is cheap regardless of training set size. Opposite of kNN's lazy, store-everything approach.
