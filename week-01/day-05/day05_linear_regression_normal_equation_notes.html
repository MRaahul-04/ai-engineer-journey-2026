Day 5 — Linear Regression: The Normal Equation

Week 1 · Day 5 of 84 · AI Engineer Journey 2026

The one-line idea

Days 1–4 built the tools. Today they assemble into your first real ML algorithm — solved by hand, no training loop, no guessing. Matmul (Day 3) + transpose + inverse (Day 4) = Linear Regression.

What does "better weights" even mean?

Error / residual = actual − predicted, one per row.

Raw errors can't just be added — positive and negative errors cancel out and hide a bad model (+1000 and −1000 → looks like 0!).

Fix (same trick as Day 2's norm): square every error before adding. Squaring kills negative cancellation AND punishes big mistakes far harder than small ones. 
SSE = Σ (actual − predicted)²   ("Sum of Squared Errors")
"Better weights" = weights that make SSE smaller. Best weights = the absolute minimum. Finding the minimum of a function = calculus territory.

The derivation — from SSE to the formula

SSE(w) = (y − Xw)ᵀ(y − Xw)
       = yᵀy − 2wᵀXᵀy + wᵀXᵀXw
Take the derivative w.r.t. w (vector calculus rules — the grown-up version of d/dw(cw)=c and d/dw(aw²)=2aw), set it to 0: 
dSSE/dw = −2Xᵀy + 2XᵀXw = 0
        XᵀXw = Xᵀy
This is literally A@x=b from Day 4. Solve the same way: 
w = (XᵀX)⁻¹ Xᵀy
XᵀX is always symmetric (Day 4 transpose rule: (XᵀX)ᵀ = XᵀXᵀᵀ = XᵀX) and always "opens upward" like a bowl — guaranteed minimum, never a maximum.

The bias trick

Add a column of 1s to X before anything else. 
X_b = np.hstack([np.ones((n,1)), X])
Now X_b @ w automatically includes the intercept — the weight attached to the 1s column is the bias, no separate +b needed.

LinearRegressionScratch — the class

class LinearRegressionScratch:
    def fit(self, X, y):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        XtX = X_b.T @ X_b
        Xty = X_b.T @ y
        self.w = np.linalg.inv(XtX) @ Xty
        return self

    def predict(self, X):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        return X_b @ self.w

    def score(self, X, y):
        y_pred = self.predict(X)
        sse = np.sum((y - y_pred) ** 2)
        sst = np.sum((y - np.mean(y)) ** 2)
        return 1 - (sse / sst)
self.w is the whole point of a class over a script — the weights survive after fit() ends, ready for predict() later. Verified against sklearn.LinearRegression — identical weights, every time.

The SSE = 0 trap

4 houses, 4 unknowns (bias+3 features) → SSE landed on exactly 0. Not because the model is smart — because equal equations & unknowns always have one exact solution (same as Day 4's square systems). Add a 5th house and SSE became a small, honest nonzero number instead.

More rows than features forces real learning instead of just memorizing/threading a needle through every point. This is the seed of overfitting.

R² — how good is the model, really?

SST = Σ(actual − mean)²      "dumb baseline": always guess the average
R²  = 1 − (SSE / SST)
  • R² = 1 → perfect fit
  • R² = 0 → no better than guessing the average every time
  • R² < 0 → actively worse than guessing the average
Student dataset scored R² = 0.9936 — matched sklearn's .score() exactly.

R² — the 4 traps (deeper dive)

1. Adding ANY feature — even random noise — never lowers R². Fix: Adjusted R² penalizes extra features that don't earn their place.
2. High R² on training data can be a lie. It measures memorization, not future performance. Must eventually be tested on unseen/held-out data (train/test split — coming later).
3. R² has no opinion on whether the relationship's SHAPE is right. A real curved pattern can score badly under a straight-line model — low R² sometimes means "wrong kind of model," not "no pattern exists."
4. R² ≠ correlation ≠ causation. High R² between two unrelated things (ice cream sales & drownings) just means a hidden third factor (heat) drives both.

Multicollinearity — breaking it on purpose

Added study_minutes = study_hours × 60 — a duplicate column, same info, different units. 
det(XᵀX) = 0.0
inv(XᵀX)  →  LinAlgError: Singular matrix
Day 4's det(A)=0 rule, now hit for real. Two columns holding the same fact → no unique set of weights exists.
Critical mistake to avoid: inv()/det() ONLY accept square matrices. Raw X or X_b is a rectangle (rows=students ≠ cols=features) — testing singularity there gives a shape error, not the real answer. Always test on XᵀX (always square, guaranteed, regardless of row count).
The fix: pinv() (pseudo-inverse) doesn't need one unique answer — it picks the smallest, most stable solution among infinite valid options. 
w = np.linalg.pinv(XtX) @ (X_b.T @ y)
w = np.linalg.pinv(X_b) @ y                    # shortcut, same answer
w, *_ = np.linalg.lstsq(X_b, y, rcond=None)    # production standard
Result: duplicate columns split the credit almost arbitrarily between them (study_hours: 0.0012, study_minutes: 0.0693) while bias/sleep/practice stayed identical. Predictions still work fine — individual weights become meaningless. lstsq's rank output confirms it: rank 4 out of 5 columns = redundancy detected automatically.

Extrapolation danger

A model happily predicted a negative house price for an extreme, never-seen combination (1 bedroom, 700 sqft, 15 yrs old) — far outside the training range. Linear models draw a straight line forever in both directions with zero awareness reality doesn't work that way. Always sanity-check predictions against the training data's actual range.
