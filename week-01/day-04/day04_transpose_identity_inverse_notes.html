Day 4 — Transpose, Identity & Inverse Matrices

Week 1 · Day 4 of 84 · AI Engineer Journey 2026

The one-line idea

Everything so far combines things (dot product, matmul). Today is about undoing — genuinely new power. This is the seed of how Linear Regression gets solved by hand, no training loop needed.

Transpose — flip the table sideways

Before: each row = one house (size, bedrooms, age) 
houses = [[1200, 3, 5],
          [800,  2, 10],
          [2000, 4, 2],
          [950,  2, 8]]     shape (4, 3)
After .T: each row = one feature, across ALL houses 
houses.T = [[1200, 800, 2000, 950],   size for every house
            [3,    2,   4,    2  ],   bedrooms for every house
            [5,    10,  2,    8  ]]   age for every house
                                       shape (3, 4)
Shape rule: (r, c) → (c, r). The numbers don't move randomly — the grouping principle flips: "rows = things" becomes "rows = descriptions."

Why transpose matters — shape compatibility

Matmul needs cols_A == rows_B. For X shape (4,3), plain X @ X crashes — 3 ≠ 4. 
X @ X.T  → (4,3)@(3,4) → (4,4)   houses compared to houses
X.T @ X  → (3,4)@(4,3) → (3,3)   features compared to features
Same two matrices, same @ — but which one you transpose completely changes the question being asked. X.T @ X is the literal first step in solving linear regression by hand.

Identity matrix — the "do nothing" matrix

Regular numbers: 7 × 1 = 7 — 1 does nothing.

Matrix version: 
I = [[1, 0],
     [0, 1]]      → np.eye(2)
1s on the diagonal, 0s everywhere else. Any matrix times I comes back untouched: A @ I = A, always (shapes permitting). Every 0 kills off everything except the matching diagonal entry — output just copies straight through.

Inverse matrix — the "undo" button

Regular numbers: to solve 5x = 20, multiply both sides by 1/5 — the number that undoes 5, because 5 × (1/5) = 1.

Matrix version: A⁻¹ is defined purely by what it does: 
A × A⁻¹ = I
If A @ x = b, left-multiply both sides by A⁻¹: 
A⁻¹ @ A @ x = A⁻¹ @ b
       I @ x = A⁻¹ @ b
           x = A⁻¹ @ b

Order matters — matrices are NOT commutative

Regular numbers: 5 × 3 = 3 × 5, always. Matrices: NOT true. A @ B ≠ B @ A in general.

To cancel A in A @ x = b, A⁻¹ must attack from the same side — left cancels left. Trying x @ A⁻¹ never touches A directly; nothing collapses to I. Also usually a straight shape mismatch.

Determinant — the gatekeeper

For a 2×2 matrix [[a,b],[c,d]]: 
det(A) = a·d − b·c
(diagonal product) − (off-diagonal product)
Example: A = [[4,7],[2,6]] → (4×6) − (7×2) = 24 − 14 = 10

If det(A) = 0 → NO inverse exists at all. Same as 1/0 — undefined, not "hard to find." Called a singular matrix — rows/columns hold redundant info, some data got "squished" away and can't be recovered.

Building the inverse — 2×2 recipe

3 steps: swap the diagonal → flip sign on the other two → divide everything by det(A). 
A = [[4, 7],      det(A) = 10
     [2, 6]]

Step 1 (swap diagonal):   [[6, 7], [2, 4]]
Step 2 (flip sign):       [[6, -7], [-2, 4]]
Step 3 (divide by 10):    [[0.6, -0.7], [-0.2, 0.4]]

A⁻¹ = [[0.6, -0.7],
       [-0.2, 0.4]]
Proof it works — top-left cell of A @ A⁻¹ should be 1: 
row0(A)·col0(A⁻¹) = (4×0.6)+(7×-0.2) = 2.4 − 1.4 = 1.0  ✓

Floating-point dust — totally normal

Computer math often gives 0.9999999999999998 instead of a clean 1.0 — decimals like 0.6 can't be stored perfectly in binary, so tiny rounding dust creeps in. Not a bug, not your mistake.

Rule: never compare floats with ==. Use np.isclose(a, b). Clean up display with: 
np.set_printoptions(precision=4, suppress=True)
suppress=True stops scientific notation (e.g. 1.2e-16) for near-zero rounding dust — shows it as 0. instead.

Square-only rule

Inverse only exists for square matrices (rows = columns) — because I is always square, and A @ A⁻¹ = I can never balance otherwise.
  • (2,2), (3,3), (50,50) → can have an inverse (if det ≠ 0)
  • (4,3), (2,5) → wrong shape entirely, no true inverse — full stop
For non-square (more rows than columns, like real datasets), the real tool is the pseudo-inverse — the seed of how real Linear Regression gets solved. Name to remember, not built by hand yet.

Solving a real system — tying it all together

4x + 7y = 40
2x + 6y = 26
This is exactly A @ [x,y] = b, with our same A and b = [40,26]. 
[x,y] = A⁻¹ @ b

x: (0.6×40) + (-0.7×26) = 24 − 18.2 = 5.8
y: (-0.2×40) + (0.4×26) = -8 + 10.4 = 2.4
Sanity check against original equations: 
4(5.8) + 7(2.4) = 23.2 + 16.8 = 40  ✓
2(5.8) + 6(2.4) = 11.6 + 14.4 = 26  ✓
No guessing, no trial and error — the inverse solved it directly.

NumPy — the real tools

np.linalg.det(A)      # determinant
np.linalg.inv(A)      # inverse
np.linalg.solve(A, b) # solves A @ x = b directly
Production habit: learn with inverse, but in real code prefer np.linalg.solve(A, b) — faster and more numerically accurate, since computing the full inverse is unnecessary extra work (same idea as not computing 1/5 separately just to then multiply by 40).
