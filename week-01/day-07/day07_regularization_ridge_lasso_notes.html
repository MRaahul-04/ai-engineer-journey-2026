Day 7 — Regularization: Ridge & Lasso

Week 1 · Day 7 of 84 · AI Engineer Journey 2026

The one-line idea

Day 5 proved adding any feature — even pure noise — can never lower R². The model happily grows huge weights to squeeze out every last drop of training fit, including fitting lucky coincidences. Today's fix: tax the loss function for having big weights, so the model stops wanting to.

Why big weights are the disease

With ~20 rows, a column of pure random numbers can, by pure chance, line up a little with y in this specific sample. The model can't tell "real signal" from "lucky coincidence" — it takes any nonzero weight that shaves off SSE, even a sliver. That's overfitting, made concrete.

With near-duplicate columns (like study_hours/study_minutes), XᵀX becomes ill-conditioned — not always a clean det=0 crash, sometimes just quietly unstable: huge, erratic, sign-flipping weights that mostly cancel out in the final prediction but are individually meaningless.

Ridge (L2) — tax the sum of squared weights

Ridge Loss = (y − Xw)ᵀ(y − Xw) + λ(wᵀw)
Derivative set to 0 (same steps as Day 5, one new term): 
−2Xᵀy + 2XᵀXw + 2λw = 0
w = (XᵀX + λI)⁻¹ Xᵀy
Same Normal Equation as Day 5 — just λI added inside the inverse. λ=0 → collapses exactly back to plain Linear Regression. Bonus: λI also nudges a singular XᵀX away from det=0 — Ridge partially fixes Day 5's multicollinearity crash for free.

Don't penalize the bias

Bias isn't a "feature weight" — it's just a baseline (e.g. average house price ≈ 200000). Penalizing it like a real weight would create a massive, pointless penalty and drag every prediction toward zero for no real reason. Fix: zero out row/col 0 of the identity matrix before adding it: I[0,0] = 0.

RidgeRegressionScratch

class RidgeRegressionScratch:
    def __init__(self, alpha=1.0):
        self.alpha = alpha

    def fit(self, X, y):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        XtX = X_b.T @ X_b
        Xty = X_b.T @ y

        n_features = X_b.shape[1]
        I = np.eye(n_features)
        I[0, 0] = 0                      # don't penalize bias

        self.w = np.linalg.inv(XtX + self.alpha * I) @ Xty
        return self

    def predict(self, X):
        ones = np.ones((X.shape[0], 1))
        X_b = np.hstack([ones, X])
        return X_b @ self.w                # identical to Day 5's predict()
Key insight: predict() never changes across algorithms — all of an algorithm's "personality" lives in fit().

alpha=100 -> [56.08, 1.16, 0.51, 0.95]
Not a clean shrink for every weight. Bias climbs (35→56) even though it's exempt — it's the escape valve picking up slack the shrinking features left behind, so the total prediction still lands near the right number. Feature 3 rose before falling — correlated features "fight over credit"; squeezing one can shift borrowed credit onto a correlated neighbor before alpha gets large enough to overpower that too.

Lasso (L1) — why it's geometrically different

Ridge's boundary is a smooth circle — loss contours can touch it anywhere, almost never exactly on an axis. Lasso's boundary is a diamond with sharp corners — contours are far more likely to first touch a pointy corner than a flat edge, and a corner touch means one weight lands exactly on an axis → exactly zero. Ridge shrinks; Lasso can delete.

Why the math breaks — and the fix

Ridge's penalty w² is a smooth bowl — has a real slope everywhere, even at w=0. Lasso's penalty |w| is a V-shape with a sharp corner exactly at w=0 — no single defined slope there, so "set derivative to 0" breaks. No closed-form matrix formula exists for Lasso.
Fix — coordinate descent: solve one weight at a time, holding the rest fixed, repeat until stable. Each single-weight update uses soft-thresholding: 
if rho >  threshold: w = rho − threshold
if rho < −threshold: w = rho + threshold
else:                 w = 0
Worked example: ρ=12, λ=5 → 7 (survives, shaved). ρ=3, λ=5 → falls in the "dead zone" (−λ to +λ) → 0 (killed outright). Bigger λ → wider dead zone → more features die.

Handling bias — centering trick

Best-fit line always passes through (mean_X, mean_y) — always, by definition of minimizing SSE. So: subtract the mean from X and y first → the centered intercept becomes exactly 0, nothing to solve for in the loop. Recover the real bias at the end: 
bias = mean_y − mean_X @ w
Proven by hand: hours=[2,4,6], scores=[50,70,90] → centered slope=10 → unwound: 30 + 10x → matches every original point exactly.

LassoRegressionScratch

class LassoRegressionScratch:
    def __init__(self, alpha=1.0, n_iterations=1000):
        self.alpha = alpha
        self.n_iterations = n_iterations

    def fit(self, X, y):
        self.mean_X, self.mean_y = X.mean(axis=0), y.mean()
        X_c, y_c = X - self.mean_X, y - self.mean_y
        n_samples, n_features = X_c.shape
        self.w = np.zeros(n_features)

        def soft_threshold(rho, threshold):
            if rho > threshold:  return rho - threshold
            elif rho < -threshold: return rho + threshold
            else: return 0

        threshold = n_samples * self.alpha
        for _ in range(self.n_iterations):
            for j in range(n_features):
                residual = y_c - X_c @ self.w + X_c[:, j] * self.w[j]
                rho_j = X_c[:, j] @ residual
                z_j = np.sum(X_c[:, j] ** 2)
                self.w[j] = soft_threshold(rho_j, threshold) / z_j

        self.bias = self.mean_y - self.mean_X @ self.w
        return self

    def predict(self, X):
        return X @ self.w + self.bias
residual = leftover error pretending feature j contributes nothing → its honest current opportunity to prove usefulness (= ρ).

The scale trap — a NEW place Day 6's lesson bites

Unscaled multicollinearity data: study_minutes survived, study_hours died instantly. After scaling: flipped — study_hours survived, study_minutes died.

Why: w[j] = soft_threshold(rho_j, threshold) / z_j — a 60x-bigger-scale feature gets a 3600x bigger z_j, so the same fixed threshold barely dents it relative to its own scale. Scale, not real importance, decided the winner. Always scale features before Ridge/Lasso — Lasso is even more sensitive than Ridge here.

Lasso's real weakness — arbitrary winners

Once truly duplicate columns are on equal footing (scaled), which one Lasso keeps is close to arbitrary — decided by loop order, not true importance. Ridge is the "team player" (splits credit smoothly); Lasso "picks a winner" and drops the rest, even among equally valid correlated features.

Elastic Net = λ1·|w| + λ2·w² — combines both: keeps Lasso's ability to zero out useless features, keeps Ridge's fairness for correlated groups. Name to remember, not built by hand yet.

Verified against sklearn

from sklearn.linear_model import Ridge, Lasso

ridge_sk = Ridge(alpha=10).fit(X, y)
lasso_sk = Lasso(alpha=10).fit(X_scaled, y)

print("Lasso scratch:", np.round(LassoRegressionScratch(alpha=10).fit(X_scaled, y).w, 4))

Interview questions — plain-language answers

Q1. Why does Ridge never hit exact zero, but Lasso can?
Ridge's penalty is a smooth curve — no sharp corner, so the optimizer just gently nudges weights down without ever needing to commit to exactly zero. Lasso's penalty has a sharp corner right at zero, creating a "dead zone" — anything weak enough falls in it and gets snapped straight to 0.
Q2. What happens as alpha → ∞ for both?
Every real feature weight gets crushed to zero — using any feature stops being worth the penalty cost. Both collapse to just predicting the average of y every time (only the untaxed bias survives).
Q3. Why does scaling matter more for Lasso than expected?
Both formulas look "algebraic" like the scale-agnostic Normal Equation, so it's tempting to assume scale doesn't matter. But Lasso's soft-threshold compares a fixed penalty against each feature's own raw-scale signal and divides by its own squared magnitude — bigger raw numbers get an easier ride, purely from units, nothing to do with real importance.
Q4. When would you pick Elastic Net?
Whenever you have groups of correlated/redundant features and don't want Lasso's "arbitrarily kill all but one" behavior, but still want the ability to zero out genuinely useless features that Ridge can never fully remove.
