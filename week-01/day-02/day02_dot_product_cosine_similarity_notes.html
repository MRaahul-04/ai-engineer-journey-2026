Day 2 — Dot Product, Norm & Cosine Similarity

Week 1 · Day 2 of 84 · AI Engineer Journey 2026

The problem we're solving

Computer only sees numbers. How do we make it know "these two things are similar" using just numbers?

Example — 3 users rating Action / Comedy / Romance (0–10): 
A = [9, 2, 1]   loves action
B = [8, 3, 2]   loves action
C = [1, 2, 9]   loves romance
Obvious to us: A and B are similar. We need the computer to figure that out too.

Dot Product — multiply matching spots, then add

Rule: multiply the numbers in the same position, add everything up. 
A · B = (9×8) + (2×3) + (1×2) = 72 + 6 + 2 = 80
A · C = (9×1) + (2×2) + (1×9) = 9 + 4 + 9 = 22
80 is much bigger than 22 → A and B agree more than A and C. It works!

Why it works: if both vectors are big in the same spot, that spot's product is huge and takes over the total. If big numbers don't line up, nothing dominates, total stays small.

The problem with plain Dot Product

Trap: a "louder" version of the same taste breaks it. 
D = [90, 20, 10]   same taste as A, just rated 10x bigger

A · D = (9×90)+(2×20)+(1×10) = 810+40+10 = 860
860 looks "more similar" than A·B (80) — but D is the SAME taste, just louder numbers. Dot product got confused by size, not actual taste. Needs a fix.

Norm — how "big" is a vector, by itself

Same Pythagoras idea from Day 1, just for any amount of numbers: square each number → add them up → square root the total. 
||A|| = √(9² + 2² + 1²) = √(81+4+1) = √86 ≈ 9.27
This measures pure "bigness" (magnitude), nothing about direction/taste.

Cosine Similarity — the real fix

Formula: take the dot product, divide out the "bigness" of both vectors. 
cosine_sim(A, B) = (A · B) / (||A|| × ||B||)

cos_sim(A,B) = 80 / (9.27 × 8.78)  ≈ 0.98   (almost same taste)
cos_sim(A,D) = 860/(9.27 × 92.7)   ≈ 1.00   (identical taste, just louder)
cos_sim(A,C) = 22 / (9.27 × 9.27)  ≈ 0.26   (barely related taste)
Always between -1 and +1. Size no longer matters — only direction (taste) does.

What the number means (no jargon)

Think of two arrows on paper starting from the same point:
  • +1 → arrows point the same way → tastes match perfectly
  • 0 → arrows point in totally unrelated directions → knowing one tells you nothing about the other
  • -1 → arrows point opposite ways → exact opposite tastes
The technical name for this is the "angle between two vectors" — but the arrow picture is all you need.

Building it from scratch (Python, no NumPy)

def dot_product_scratch(v1, v2):
    total = 0
    for i in range(len(v1)):
        total += v1[i] * v2[i]     # multiply + add together
    return total

def norm_scratch(v):
    total = 0
    for i in range(len(v)):
        total += v[i]**2           # square each number
    return math.sqrt(total)        # then square root the sum

def cosine_similarity_scratch(v1, v2):
    return dot_product_scratch(v1, v2) / (norm_scratch(v1) * norm_scratch(v2))
Common bug to remember: compute-then-throw-away. Always write total += v1[i] * v2[i] in ONE line — don't multiply on one line and add something else on the next.

NumPy version — same math, 2 lines

dot = np.dot(user_A, user_B)
norm_A = np.linalg.norm(user_A)
norm_B = np.linalg.norm(user_B)
cosine_sim = dot / (norm_A * norm_B)
Same answer as the scratch version. NumPy runs the loop inside fast compiled C code instead of slow Python — matters hugely once you have millions of comparisons.

Matrix vs Vector — compare one user to everyone at once

users = [[9,2,1], [8,3,2], [1,2,9], [90,20,10]]   # shape (4,3)

np.dot(users, user_A)   →  [86, 80, 22, 860]
One line replaces 4 separate dot products. Each row of the matrix gets dot-producted against the vector automatically.

Matrix vs Matrix — everyone compared to everyone

similarity = np.dot(users, users.T)     # .T flips rows into columns
Result is a grid: row i, column j = dot product of user i and user j.
  • Grid is symmetric → row0-col1 always equals row1-col0
  • Diagonal = each user dot-producted with themselves = biggest number in its row
  • This exact trick (matrix times its own transpose) is the core computation inside Transformer attention

Turning the raw grid into real Cosine Similarity

norms = np.linalg.norm(matrix, axis=1)     # norm of every row, in one line
norm_matrix = np.outer(norms, norms)       # entry [i,j] = norms[i] × norms[j]
cosine_matrix = similarity / norm_matrix   # divide grid by grid, position by position
np.outer(a, b) → builds every pairwise multiplication into a grid, so it lines up perfectly with the similarity grid for one clean division. Diagonal of the final cosine grid is always exactly 1.0 (self vs self = perfect match).
