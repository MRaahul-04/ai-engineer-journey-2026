Day 3 — Matrix Multiplication & NN Layers

Week 1 · Day 3 of 84 · AI Engineer Journey 2026

The one-line idea

Matrix multiplication is Day 2's dot product, repeated — once for every (row of A, column of B) pair. Nothing new is being invented here, just an old operation looped over a grid.

The shape rule

Rule: A @ B only works if cols_A == rows_B. The matching middle number "cancels out." 
(rows_A, cols_A) @ (rows_B, cols_B) → (rows_A, cols_B)
Example: (2,3) @ (3,2) → (2,2). The 3s must agree; only the outer 2 and 2 survive into the result's shape.

Row meets column — worked example

A = [[1,2,3],      B = [[7, 8],
     [4,5,6]]           [9, 10],
                        [11,12]]

C[0][0] = row0(A)·col0(B) = 1×7 + 2×9  + 3×11 = 58
C[0][1] = row0(A)·col1(B) = 1×8 + 2×10 + 3×12 = 64
C[1][0] = row1(A)·col0(B) = 4×7 + 5×9  + 6×11 = 139
C[1][1] = row1(A)·col1(B) = 4×8 + 5×10 + 6×12 = 154

C = [[58, 64],
     [139,154]]
Every output cell = one dot product between a specific row and a specific column. Nothing more mysterious than that.

Matmul from scratch — 3 nested loops

Structure: outer loop = row of A, middle loop = column of B, inner loop = walk-multiply-accumulate (this inner loop is dot_product_scratch from Day 2). 
def matmul_scratch(A, B):
    rows_A = len(A)
    cols_A = len(A[0])
    cols_B = len(B[0])

    C = []
    for i in range(rows_A):        # pick a row of A
        row_result = []
        for j in range(cols_B):    # pick a column of B
            total = 0                # fresh zero per (i, j) pair
            for k in range(cols_A):
                total += A[i][k] * B[k][j]
            row_result.append(total)  # save finished number
        C.append(row_result)
    return C

Bugs I actually hit — keep these in mind

1. Wrong start value: row_result = [] is a list, not a running total. total must start at 0 (a number) — one fresh total per (i, j) pair, reset every time j changes.
2. Forgetting to save the finished number: once the k loop ends, total holds one finished value — it must be explicitly row_result.append(total)'d, or it's silently thrown away.
3. Case-sensitive variable mismatch: c = [] vs C.append(...) → Python sees these as two different variables → NameError.
4. @ needs NumPy arrays, not lists: x @ W crashes with TypeError if x and W are plain Python lists. Must be np.array(x) @ np.array(W).

NumPy version — one symbol

import numpy as np
C = np.array(A) @ np.array(B)
Same rule (cols_A == rows_B), same result, zero loops. This exact @ is the operation running inside every layer of every neural network, millions of times per second.

@ vs dot product vs cosine similarity

On two 1-D vectors, A @ B and np.dot(A, B) give the identical number — vector dot product is just the 1-D special case of matmul.

But @ stops there. It only ever multiplies-and-sums. It has no idea of "square root" or "divide," so:
  • Norm still needs np.linalg.norm(v) — a separate function
  • Cosine similarity still needs the manual division step afterward: (A @ B) / (norm_A * norm_B)
@ replaces the dot-product step only — never the full formula.

A neural network layer — the whole thing

Formula: 
output = ReLU((x @ W) + b)
x = input row  |  W = learned weights matrix  |  b = bias  |  ReLU = activation

Worked by hand: 
x = [2, 3],  W shape (2,3),  b = [1, 1, 0]

x @ W = [2, 3, 7]
+ b    = [3, 4, 7]
ReLU   = [3, 4, 7]   (nothing negative, nothing clipped)
Stack this same formula layer after layer — that IS a deep neural network. No extra magic at scale, just this, repeated.

ReLU — why it matters, not just what it does

Rule: max(0, x) — negative becomes 0, positive passes through untouched. Not "smart," just always keeps the bigger of two numbers. 
b = [1, -5, -2]  →  x@W + b = [3, -2, 5]  →  ReLU → [3, 0, 5]
Why it exists: without ReLU (or any activation), stacking 100 linear layers mathematically collapses into just one linear layer. ReLU's clipping is what makes each layer capable of learning something genuinely different — it's the source of a network's ability to learn curves and complex boundaries, not straight lines.

Vectorized version (whole array at once, no loop): np.maximum(0, z) — this is NumPy's array-aware big brother of Python's single-number max(0, x).
